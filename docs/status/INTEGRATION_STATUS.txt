--- 1. AUTH MODULE ---
Frontend: src/api/auth.ts + src/api/client.ts
Backend:  AuthController.java (/api/v1/auth)

  ENDPOINT PATHS:
  ✅ POST /auth/login          — matches
  ✅ POST /auth/logout         — matches  
  ✅ GET  /auth/me             — matches
  ❌ POST /auth/refresh        — DOES NOT EXIST in backend
  ❌ POST /auth/change-password — DOES NOT EXIST in backend

  ISSUES TO FIX:

  Issue A1: Dead refresh token code in client.ts (lines 54-83)
    Frontend tries to call /auth/refresh on 401.
    This endpoint doesn't exist. The code will always fail silently and
    redirect to login, which is correct behavior — but the dead code
    should be removed to avoid confusion.
    ACTION: Remove lines 54-83 in client.ts. On 401, directly clear
    localStorage and redirect to /login.

  Issue A2: LoginResponse type mismatch
    Frontend expects: { accessToken, tokenType, expiresAt, refreshToken, user }
    Backend returns:  { accessToken, user }
    The fields "tokenType", "expiresAt", "refreshToken" don't exist in
    the backend LoginResponse record.
    ACTION: Remove tokenType, expiresAt, refreshToken from LoginResponse
    interface. Or make them all optional (they already are optional for
    refreshToken, but tokenType and expiresAt are required in the type).

  Issue A3: UserInfo extra fields
    Frontend expects: username, departmentId, departmentName, plantId,
    plantName, permissions
    Backend returns:  userId, employeeNumber, employeeId, displayName,
    email, roles
    The extra fields (departmentId, plantId, etc.) are NOT in the backend
    response. They are marked optional in frontend, so won't crash, but
    will always be undefined.
    ACTION: No break, but UI that depends on these will show blanks.

  Issue A4: .env file has JavaScript comment syntax
    Line 1: "// Environment variables"
    .env files don't support // comments. This line will be treated as
    an env variable name, not a comment.
    ACTION: Remove line 1 or change to # comment.
