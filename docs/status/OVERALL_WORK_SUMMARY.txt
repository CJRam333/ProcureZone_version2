SESSION 4: FRONTEND INTEGRATION Q&A (Feb 27, 2026)
================================================================================

What we did:
  - Answered 8 critical frontend integration questions
  - Researched each answer directly from source code

Questions answered:

  Q1: PO Status Enum — What are exact backend values?
  A1: 1-based: 1=Draft, 2=Submitted, 3=Approved, 4=Sent to Vendor,
      5=Partially Received, 6=Fully Received, 7=Cancelled, 8=Closed
      (from PurchaseOrder.java)

  Q2: GRN Status Enum — What are exact backend values?
  A2: 1-based: 1=Created, 2=Inspected, 3=RM Approved, 4=Approved,
      5=Final Approved, 6=Stored, 7=Rejected
      (from GoodsReceipt.java)

  Q3: Issue Note Status Enum — What are exact backend values?
  A3: 1-based with 10 values: 1=Created, 2=Pending RM Approval,
      3=RM Approved, 4=Approved, 5=Rejected by RM, 6=Rejected by Manager,
      7=Pending Store Issue, 8=Issued, 9=Rejected by Stores, 10=Returned
      (from IssueNote.java)

  Q4: Auth Refresh Token — Does /auth/refresh exist?
  A4: NO. Only 3 auth endpoints exist: login, logout, /me.
      JWT expires after 1 hour. No silent refresh mechanism.

  Q5: GRN QC Endpoint — What's the exact path?
  A5: POST /api/v1/grn/{id}/inspect (NOT /qc)
      Also: base path is /api/v1/grn (singular, NOT /grns)

  Q6: Dashboard Endpoints — Complete list?
  A6: 13 endpoints under /api/v1/dashboard:
      /statistics, /summary, /indents/stats, /purchase-orders/stats,
      /goods-receipts/stats, /issue-notes/stats, /inventory/stats,
      /vendors/stats, /trends/monthly, /breakdown/department,
      /top-materials, /pending-approvals, /alerts

  Q7: Inventory Response Format — Page<T> or custom?
  A7: Custom wrapper: { "success": true, "count": N, "data": [...] }
      Does NOT use Spring Page<T>

  Q8: Which commented-out features are planned?
  A8: None are in the backend. Stock Transfer, Vendor Bulk Import,
      Reconciliation do not exist. Safe to leave disabled in frontend.

SESSION 9: PLANT INDENT MODULE OVERHAUL (March 21–22, 2026)
Developer: CJRam_NSL
================================================================================

What we did:

  BACKEND — Entity & Repository:
  - Diagnosed silent failures: application was targeting wrong legacy table
    (pz_tbl_indent_master instead of pz_tbl_indent_masterb).
  - Completely re-wrote PlantIndent.java JPA entity to map to pz_tbl_indent_masterb.
  - Decoupled strict @ManyToOne relationships causing "Unable to find UnitOfMeasure"
    runtime exceptions on form submit.
  - Replaced with direct integer ID field mappings for legacy schema compatibility.
  - Refactored PlantIndentRepository.java — stripped broken @EntityGraph annotations.
  - Rewrote all JPQL queries using simple field access instead of deep entity graphs.

  BACKEND — Service Layer:
  - Rebuilt PlantIndentService.java with null-safety guards (> 0 checks on IDs).
  - Implemented dynamic entityManager.find() lookups inside mapToResponse()
    to restore plantName, cropTypeName, batchNumber, statusDescription in payloads.
  - Stabilized the 8-tier status lifecycle:
    Draft → Pending DEO → Pending Manager → Approved → Processing → Completed.

  DATABASE:
  - Seeded pz_crop_type table with mock categorical data:
    Cotton, Maize, Rice, Soybean, Wheat, Vegetables, Oilseeds, Pulses,
    Sugarcane, Fruits, Spices.

  FRONTEND — Form (PlantIndentFormPage.tsx):
  - Fixed transformFormData: was sending wrong fields to backend.
    Now correctly maps: cropType→outputMaterial, cropGroup→packProcess,
    deliveryDate→outputDescription.
  - Removed dead Zod schema validations (companyId, departmentId) causing
    completely silent form submission drops.
  - Added UOM auto-population on material selection via useEffect.

  FRONTEND — List (PlantIndentListPage.tsx):
  - Restored Crop Type / Plant columns from outputMaterial/cropTypeName fallback fields.
  - Added UOM column that was missing.
  - Added row-level Edit and Delete action buttons with status-aware toggles.

  FRONTEND — Detail View (PlantIndentDetailPage.tsx):
  - Created dedicated read-only view page from scratch.
  - Displays Plant/Employee Info, Crop/Production details, QC Parameters
    (STL, ODV, GOT, ELISA, Moisture, Pure Seed, Germ Normal), Material line items.
  - Added Edit/Delete buttons with appropriate status restrictions.

  FRONTEND — Routing (router.tsx):
  - /plant-indent/:id → PlantIndentDetailPage (read-only view)
  - /plant-indent/:id/edit → PlantIndentFormPage (edit form)
