## Role Overview

### Description

The **Super Admin** is the highest privileged user in the ProcureZone system with unrestricted access to all modules, configurations, and administrative functions. This role is responsible for system-wide configuration, user management, master data oversight, and critical system operations.

### Hierarchy Position

```
Super Admin (Level 0 - Highest)
  ├── Admin (Level 1)
  ├── Department Heads (Level 2)
  ├── Procurement (Level 2)
  ├── Plant Managers (Level 2)
  └── All Other Roles (Level 3-4)
```

### Permissions Matrix

| Permission       | Access Level   |
| ---------------- | -------------- |
| View             | ✅ ALL MODULES |
| Add              | ✅ ALL MODULES |
| Edit             | ✅ ALL MODULES |
| Delete           | ✅ ALL MODULES |
| System Config    | ✅ YES         |
| User Management  | ✅ YES         |
| Role Assignment  | ✅ YES         |
| Audit Log Access | ✅ FULL ACCESS |

## User Stories

### 1. Master Data Management

#### 1.1 Company Management

**As a Super Admin**, I can:

- Create new company entities in the system
- Update existing company information (name, code, status)
- Deactivate companies (soft delete)
- View complete audit trail of company changes
- Restore accidentally deactivated companies

**Acceptance Criteria**:

- Company code must be unique
- Cannot delete company if referenced by employees or indents
- All changes must be logged in audit table
- Can override business rules if necessary

**API Endpoints Required**:

```
✅ POST   /api/v1/companies
✅ GET    /api/v1/companies
✅ GET    /api/v1/companies/{id}
✅ PUT    /api/v1/companies/{id}
✅ DELETE /api/v1/companies/{id}
```

#### 1.2 Department Management

**As a Super Admin**, I can:

- Create organizational departments
- Assign department codes and names
- Link departments to companies and locations
- Map departments to sections
- View department hierarchy
- Manage department head assignments

**Acceptance Criteria**:

- Department code unique within company
- Can create cross-functional departments
- Can view all employees in a department
- Can reassign employees between departments

**API Endpoints Required**:

```
✅ POST   /api/v1/departments
✅ GET    /api/v1/departments
✅ GET    /api/v1/departments/{id}
✅ PUT    /api/v1/departments/{id}
✅ DELETE /api/v1/departments/{id}
❌ GET    /api/v1/departments/{id}/employees
❌ POST   /api/v1/departments/{id}/sections
```

#### 1.3 Location/Plant Management

**As a Super Admin**, I can:

- Create new locations (offices, plants, warehouses)
- Define location codes and addresses
- Link locations to companies
- Assign plants to locations
- Manage plant-specific configurations
- View location hierarchy

**Acceptance Criteria**:

- Location code unique across system
- Can have multiple plants per location
- Can assign multiple departments to a location
- Location deactivation prevents new assignments

**API Endpoints Required**:

```
❌ POST   /api/v1/locations
❌ GET    /api/v1/locations
❌ GET    /api/v1/locations/{id}
❌ PUT    /api/v1/locations/{id}
❌ DELETE /api/v1/locations/{id}
❌ GET    /api/v1/locations/{id}/plants
❌ POST   /api/v1/plants
```

#### 1.4 Material Master Management

**As a Super Admin**, I can:

- Create new material items
- Define material codes, names, descriptions
- Categorize materials by type
- Link materials to units of measure
- Assign materials to specific plants
- Set material-specific approval thresholds
- Import bulk material data from CSV

**Acceptance Criteria**:

- Material code unique within plant
- Must specify unit of measure
- Can have plant-specific material codes
- Can upload material specifications (PDFs, images)

**API Endpoints Required**:

```
✅ POST   /api/v1/materials
✅ GET    /api/v1/materials
✅ GET    /api/v1/materials/{id}
✅ PUT    /api/v1/materials/{id}
✅ DELETE /api/v1/materials/{id}
❌ POST   /api/v1/materials/bulk-import
❌ GET    /api/v1/materials/{id}/specifications
❌ POST   /api/v1/materials/{id}/specifications
```

#### 1.5 Unit of Measure Management

**As a Super Admin**, I can:

- Define standard units of measure (KG, LITRE, PCS, METER, etc.)
- Create custom units for specific materials
- Set conversion factors between units
- Deactivate obsolete units

**Acceptance Criteria**:

- UOM code unique and uppercase
- Cannot delete if used in materials
- Must support decimal quantities
- Can define compound units (e.g., KG/METER)

**API Endpoints Required**:

### 2. User & Role Management

#### 2.1 Employee Management

**As a Super Admin**, I can:

- Create new employee records
- Assign employee to company, department, location
- Set employee designation and cost center
- Activate/deactivate employee accounts
- Reset employee passwords
- View employee assignment history
- Transfer employees between departments/locations

**Acceptance Criteria**:

- Employee ID and email must be unique
- Must assign at least one role
- Can assign multiple roles to an employee
- Password must meet security requirements
- Deactivated employees cannot log in but retain history

**API Endpoints Required**:

```
❌ POST   /api/v1/employees
❌ GET    /api/v1/employees
❌ GET    /api/v1/employees/{id}
❌ PUT    /api/v1/employees/{id}
❌ DELETE /api/v1/employees/{id}
❌ POST   /api/v1/employees/{id}/reset-password
❌ POST   /api/v1/employees/{id}/transfer
❌ GET    /api/v1/employees/{id}/assignment-history
```

#### 2.2 Role Assignment

**As a Super Admin**, I can:

- Assign multiple roles to an employee
- Remove roles from employees
- Create custom role combinations
- View all employees with a specific role
- Override role-based restrictions temporarily
- Define role hierarchies and inheritance

**Acceptance Criteria**:

- An employee can have 1-14 roles
- Role changes logged in audit table
- Cannot remove last admin role from system
- Role changes take effect immediately

**API Endpoints Required**:

```
❌ POST   /api/v1/employees/{id}/roles
❌ GET    /api/v1/employees/{id}/roles
❌ DELETE /api/v1/employees/{id}/roles/{roleId}
❌ GET    /api/v1/roles/{roleId}/employees
❌ POST   /api/v1/roles/{roleId}/permissions
```

#### 2.3 User Account Management

**As a Super Admin**, I can:

- Create user login accounts linked to employees
- Reset forgotten passwords
- Unlock locked accounts
- Force password change on next login
- View user login history
- Disable accounts temporarily
- View active sessions and force logout

**Acceptance Criteria**:

- Username must be unique (usually email)
- Password hashed with BCrypt
- Failed login attempts tracked (lock after 5 attempts)
- Can set account expiry dates
- Can require 2FA for specific users

**API Endpoints Required**:

```
❌ POST   /api/v1/users
❌ GET    /api/v1/users
❌ GET    /api/v1/users/{id}
❌ PUT    /api/v1/users/{id}
❌ POST   /api/v1/users/{id}/reset-password
❌ POST   /api/v1/users/{id}/unlock
❌ GET    /api/v1/users/{id}/login-history
❌ POST   /api/v1/users/{id}/force-logout
```

**As a Super Admin**, I can:

- Define workflow routing rules
- Configure email notification templates
- Set fiscal year and date formats
- Configure backup schedules

**Acceptance Criteria**:

### 4. Reporting & Analytics

#### 4.1 Audit Log Review

**As a Super Admin**, I can:

- View complete audit trail of all system operations
- Filter audit logs by:
  - Date range
  - User/employee
  - Action type (CREATE, UPDATE, DELETE)
  - Entity type (Company, Indent, Material, etc.)
  - Status (SUCCESS, FAILED)
- Export audit logs to CSV/PDF
- Search audit logs by keyword
- View detailed change history for any record

**Acceptance Criteria**:

- Audit logs cannot be modified or deleted
- Can view up to 5 years of history
- Export includes all relevant fields
- Can trace complete lifecycle of an indent

**API Endpoints Required**:

```
✅ GET    /api/v1/audit-logs (basic)
❌ GET    /api/v1/audit-logs/advanced (with filters)
❌ GET    /api/v1/audit-logs/export
❌ GET    /api/v1/audit-logs/entity/{type}/{id}
❌ GET    /api/v1/audit-logs/user/{userId}
```

### 5. Emergency Operations

#### 5.1 Override Capabilities

**As a Super Admin**, I can:

- Force-approve stuck indents
- Override approval workflows in emergencies
- Unlock any record for editing
- Reverse completed transactions (with justification)
- Bypass validation rules temporarily
- Manually trigger background jobs

**Acceptance Criteria**:

- All overrides require mandatory comments/justification
- Overrides logged separately with high visibility
- Cannot override financial year closure
- Email notifications sent for critical overrides

**API Endpoints Required**:

```
❌ POST   /api/v1/admin/force-approve/{indentId}
❌ POST   /api/v1/admin/unlock-record
❌ POST   /api/v1/admin/reverse-transaction
❌ POST   /api/v1/admin/bypass-validation
❌ POST   /api/v1/admin/trigger-job
```

#### 5.2 Data Management

**As a Super Admin**, I can:

- Export complete database backup
- Import historical data
- Purge old records (with confirmation)
- Run data integrity checks
- Repair inconsistent data
- Migrate data between environments

**Acceptance Criteria**:

- Integrity checks generate detailed reports

## Typical Daily Workflows

### Morning Routine

1. Review overnight audit logs for anomalies
2. Check system health dashboard
3. Review pending critical approvals
4. Process user account requests (new/reset password)
5. Review overnight batch job results

### On-Demand Tasks

- Create new employees joining the organization
- Assign roles based on HR requests
- Configure new departments/locations
- Resolve access issues escalated by users
- Generate ad-hoc reports for management
- Investigate audit trail for compliance queries

### Periodic Tasks

- **Weekly**: Review approval bottlenecks, user activity reports
- **Monthly**: System health checks, backup verification
- **Quarterly**: Role assignment audit, inactive user cleanup
- **Yearly**: Fiscal year rollover, master data cleanup

## Access Restrictions (What Super Admin CANNOT Do)

Even Super Admin has some constraints:

1. ❌ Cannot delete the last Super Admin account
2. ❌ Cannot modify audit logs (read-only)
3. ❌ Cannot bypass financial year closure for closed periods
4. ❌ Cannot delete records with dependencies (must archive)
5. ❌ Must provide justification for critical overrides

## Security Considerations

1. **Audit Everything**: All Super Admin actions must be logged
2. **Two-Person Rule**: Consider requiring approval from another Super Admin for critical operations
3. **Session Timeout**: Shorter timeout for Super Admin sessions (15 minutes)
4. **IP Restrictions**: Optionally restrict Super Admin access to specific IP ranges
5. **2FA Mandatory**: Consider requiring 2FA for all Super Admin accounts
6. **Regular Reviews**: Quarterly review of who has Super Admin access
