BACKGROUND
----------
The ProcureZone frontend (React 19 + TypeScript + Vite) was built with 
placeholder API paths, 0-based status enums, and 16 frontend-only roles.
The backend (Spring Boot 3.2.5 + Java 21 + MySQL 8.0) uses different paths,
1-based status enums, and 9 roles. This document covers every change made
to align the two systems.


================================================================================
PART 1: STATUS ENUM CORRECTIONS (0-based → 1-based)
================================================================================

All status enums in the frontend were starting from 0. The backend uses 1-based
values from database tables. We fixed all four modules:

FILE: src/api/indents.ts
  BEFORE: DRAFT=0, PENDING_APPROVAL=1, L1_APPROVED=2, L2_APPROVED=3, 
          FULLY_APPROVED=4, REJECTED=5, PO_GENERATED=6, CANCELLED=7
  AFTER:  DRAFT=1, SUBMITTED=2, DEPTHEAD_APPROVED=3, FINANCE_APPROVED=4,
          PROCUREMENT_APPROVED=5, REJECTED=6, ON_HOLD=7, COMPLETED=8

FILE: src/api/purchaseOrders.ts
  BEFORE: DRAFT=0, PENDING_CONFIRMATION=1, CONFIRMED=2, PARTIALLY_RECEIVED=3,
          FULLY_RECEIVED=4, CANCELLED=5, CLOSED=6
  AFTER:  DRAFT=1, SUBMITTED=2, APPROVED=3, SENT_TO_VENDOR=4,
          PARTIALLY_RECEIVED=5, FULLY_RECEIVED=6, CANCELLED=7, CLOSED=8

FILE: src/api/grn.ts
  BEFORE: DRAFT=0, PENDING_QC=1, QC_APPROVED=2, QC_REJECTED=3, POSTED=4,
          CANCELLED=5
  AFTER:  CREATED=1, INSPECTED=2, RM_APPROVED=3, APPROVED=4,
          FINAL_APPROVED=5, STORED=6, REJECTED=7

FILE: src/api/issueNotes.ts
  BEFORE: DRAFT=0, PENDING_APPROVAL=1, APPROVED=2, ISSUED=3,
          PARTIALLY_ISSUED=4, REJECTED=5, CANCELLED=6, CLOSED=7, RETURNED=8
  AFTER:  CREATED=1, PENDING_RM_APPROVAL=2, RM_APPROVED=3,
          APPROVED_BY_MANAGER=4, REJECTED_BY_RM=5, REJECTED_BY_MANAGER=6,

PART 6: BUSINESS LOGIC NOTES (from backend guide)
================================================================================

  1. SUPERVISOR BYPASS: Both GRN and Issue Note have a supervisorBypass flag.
     When true, the RM (Reporting Manager) approval step is skipped.
     - GRN: status jumps from 2 (Inspected) → 4 (Approved)
     - Issue Note: status jumps from 2 (Pending RM) → 4 (Manager Approved)

  2. AUTH: No refresh token endpoint exists. JWT expires after 1 hour.
     Frontend should handle 401 by redirecting to login page.

  3. INVENTORY: Uses custom { success, count, data } response wrapper,
     NOT the standard Spring Page<T> format used by other modules.

  4. PAGINATION: All paginated endpoints use 0-indexed pages (page=0 is first).

  5. PO AMENDMENT: Repository exists but NO REST endpoint is exposed yet.
     Frontend PO amendment page may not work against backend.
